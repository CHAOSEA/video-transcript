## 图文正文草稿

这是一个视频转录 CLI，最近也加上了 Codex 项目 Skill。输入在线视频链接后，工具先尝试获取人工或自动字幕；没有可用字幕且平台允许媒体访问时，再下载音轨或带音轨视频，在本机用 CPU 做语音识别。除了利用已有字幕，它也提供无字幕时的本地 ASR 路径，实际能否使用仍由平台访问条件决定。

CLI 会生成两份文件：

- `transcript.md`：带时间轴、方便阅读的逐字稿
- `evidence.json`：保留原始分段、来源、模型和运行信息，便于回看结果是怎么来的

如果在 Codex 中明确要求分析，项目 Skill 可以基于逐字稿另存 `analysis.md`，整理摘要、观点和对应时间戳，不改写原始转录。这一步由当前 Agent 模型完成，逐字稿会进入该模型的处理上下文；CLI 本身不生成分析稿。

此前对 YouTube 使用了 5 条公开视频做字幕、解析和媒体传输诊断；2 条人工字幕、1 条自动字幕路径通过，一条无字幕视频曾通过音轨下载和本机 ASR，但 2026-10-20 对同一样本复测时在元信息阶段收到 HTTP 403。Bilibili 在 R0 检查了 6 个公开视频，R1 又检查 3 个页面，其中一条完成无字幕音轨转录；小红书经过多轮 URL、网络和 HTTPS 媒体诊断后，有一条公开视频完成端到端转录。抖音公开样本仍在元信息前遇访问限制。当前 104 项自动化回归测试单独统计，不等于 104 条真实视频。

完整范围和具体状态见 README 的[在线平台实测矩阵](../online-support-matrix.md)。样本测试说明哪些路径曾经跑通，不代表所有视频都能处理。

所以这不是“四个平台全部畅通”的承诺。平台可能要求验证、没有字幕或无法提供可访问媒体；遇到这些情况，工具会报告限制，不读取浏览器 Cookie，也不绕过平台检查。

原始识别分段会保存在证据文件里，逐字稿负责展示时间轴；Codex 生成的分析稿则另存一份。现在还没有人工校订稿 CER 基准，因此不宣称某个模型准确率最高。
